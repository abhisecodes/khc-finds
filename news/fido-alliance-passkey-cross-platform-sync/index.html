FIDO Alliance Expands Cross-Platform Passkey Credential Exchange Specifications

New cryptographic drafts for Credential Exchange Protocol (CXP) and Format (CXF) enable secure passkey transfer between competing operating systems and password managers.

By KHC Tech Desk
• Published Oct 8, 2026
• 4 min read
• FIDO Alliance Standard

While passkeys (built on the W3C WebAuthn standard) have made substantial progress replacing vulnerable text passwords, their greatest consumer hurdle has been vendor lock-in. Passkeys generated inside Apple Keychain, Google Password Manager, or Microsoft Entra have historically remained trapped within their respective platform silos, discouraging users from adopting passkeys across mixed-device workflows.

The FIDO Alliance has addressed this barrier with the release of its standardized Credential Exchange Protocol (CXP) and Credential Exchange Format (CXF) working group specifications.

How Cryptographic Passkey Exchange Works

Passkeys are fundamentally asymmetric cryptographic key pairs: a public key registered with the web service (such as Amazon or Google), and a private key secured within the client device’s Trusted Execution Environment (TEE) or encrypted cloud vault.

Transferring private keys across different software vendors presents extreme security risks. A plain CSV export (common with traditional passwords) would expose private signing keys to malware. The new FIDO CXP protocol solves this through end-to-end encrypted device-to-device tunneling:

  • Out-of-Band Pairing: The sending and receiving applications establish an authenticated ECDH (Elliptic-Curve Diffie-Hellman) channel, verified via a one-time visual QR code or NFC contact.
  • Zero Intermediate Knowledge: Private keys are encrypted in-memory by the source provider and can only be decrypted inside the target provider’s enclave. No intermediate cloud servers or local file systems handle unencrypted keys.
  • CXF Standardization: The payload format encapsulates WebAuthn credentials, user handle mappings, and credential metadata uniformly across 1Password, Bitwarden, Dashlane, Apple, and Google.

Confirmed Protections vs. Remaining Implementation Hurdles

Confirmed Security Guarantees

The specification strictly prohibits bulk silent export. Every credential transfer requires explicit biometric user presence (fingerprint or face unlock) and generates verifiable audit log events on both host devices.

Remaining Friction Points

While third-party password managers have pledged immediate compliance, native OS platform vendors must roll out corresponding API hooks in future operating system updates before browser-level imports become fully automatic for non-technical users.

"Passwordless authentication only works when users feel in complete control of their credentials. Standardized migration removes the psychological fear of being locked into a single ecosystem."

Consumer Recommendations for Passkey Migration

For individuals and small teams managing accounts across Windows, Android, and macOS workstations, security engineers recommend maintaining passkeys in dedicated multi-platform vaults or utilizing hardware security keys (FIDO2) for root-level recovery until CXP implementations reach full commercial maturity in early 2027.
